# V2.5 手势绑定与手势系统开放 — 设计

## 1. 背景与目标

v2.4 系列已完成链接可靠性闭环（真实 Chrome 门可用）与文档体系整改（中文文件名 + v1/v2 归类）。V2.5 开放两个方向：

1. **开放手势 → 浏览器动作的绑定关系**：用户可把"三指点击"重绑为"刷新"等，不再写死默认映射。
2. **开放手势系统（预设集）**：识别器支持 2/3/4 指手势，用户可启用"二指左右滑动 = 切换 tab"等预设。

**目标**：用户在控制中心可配置"手势 → 动作"映射并立即生效；识别器支持预设多指手势，现有三指手势识别不退化。

## 2. 现状基础（已核验）

| 层 | 现状 | 关键证据 |
|---|---|---|
| 绑定模型 | `BindingRule`（gestureDefinitionId → actionId + contextConstraints + priority + enabled）**已定义并接入 `RuleEngine`/`BindingResolver`** | `BindingModels.swift`、`RuleEngine.swift:3/50` |
| 默认绑定 | `DefaultRules.v1Bindings` 硬编码 6 条（三指点击→开链接/切tab/关tab、滑动→切tab） | `DefaultRules.swift` |
| 手势定义 | `GestureDefinition` 已参数化 `fingers`（默认全 3）、primitive（tap/swipe）、direction、region | `BindingModels.swift` |
| 识别器 | **`GestureRecognizer.swift:54` 硬编码 `fingerCount == 3`**，只认三指；`ComposedGesture`/`GestureType` 为 6 个三指固定枚举 | `GestureRecognizer.swift` |
| 配置 | `SettingsStore` 已持久化 `[Rule]` + `AppConfiguration` | `SettingsStore.swift` |
| 触控数据 | `MultitouchSupportBackend` 提供 `TouchFrame(activeTouches)` 全量触点（可区分手指数） | `MultitouchSupportBackend.swift` |

## 3. 设计决策（grilling 共识）

| 决策点 | 结论 |
|---|---|
| 版本范围 | V2.5 大版本：绑定开放 + 手势系统同做 |
| 绑定开放范围 | 手势→动作映射用户可配；上下文（链接上 vs 空白处）**系统预设**，UI 不开放 |
| 动作面 | 现有 7 个标准动作 + 新增 **Tab 管理类**（开新标签/固定/静音/关闭其他/恢复关闭）+ **链接页面类**（复制链接/复制URL/滚动顶底） |
| DIY 粒度 | **预设手势集**（识别器定义集驱动），不做 DIY 编辑器 |
| 识别器重构 | **增量参数化**：`fingerCount == 3` → 按手势定义集匹配；保留 session 状态机 + classify |
| 二指滑动 | 二指**左右**滑避开系统「页面间轻扫」：App 检测 + 引导用户关闭；垂直二指滑动（滚动）不占用 |

## 4. 架构与数据流

```
Trackpad Hardware
  → MultitouchSupportBackend（TouchFrame: activeTouches）
  → GestureRecognizer（定义集驱动：fingerCount/primitive/direction/region 匹配）
  → RecognizedGesture（ComposedGesture）
  → RuleEngine / BindingResolver（BindingRule 配置化：默认 + 用户覆盖）
  → ActionDescriptor（StandardActionID，含新增动作）
  → Provider → Chrome Extension
```

配置流：`SettingsStore（用户绑定配置 + 手势定义集）→ RuleEngine / GestureRecognizer`。

## 5. 关键模型扩展

| 模型 | 扩展 |
|---|---|
| `GestureDefinition` | 新增预设：`two-finger-swipe-left/right`、`four-finger-tap`、`four-finger-swipe-left/right` 等；`fingers` 参数化真正生效 |
| `ComposedGesture` / `GestureType` | 新增对应 case（**向后兼容**，新增枚举 case 不破坏既有解码） |
| `BindingRule` | 成为用户可配置项：默认 `v1Bindings` + 用户覆盖（persisted） |
| `StandardActionID` | 新增 Tab 管理类（`browser.tab.open_new` / `browser.tab.pin` / `browser.tab.unpin` / `browser.tab.toggle_mute` / `browser.tab.close_others` / `browser.tab.restore`）+ 链接页面类（`browser.link.copy` / `browser.page.copy_url` / `browser.page.scroll_top_bottom`） |
| 新增 | 用户绑定配置模型 + `SettingsStore` 持久化 + 控制中心绑定 UI + 系统手势检测 |

## 6. 识别器增量参数化

- `observe`：`fingerCount == 3` 写死 → 按**活跃手势定义集**（含各自 fingerCount）匹配当前帧手指数。
- 保留 session 状态机语义：手指数升高 → reject + `requiresAllTouchesLift`；降低 → classify；抬指 → classify。
- `classify`：按命中定义的 primitive/direction/region 输出对应 `ComposedGesture`（tap → 区域/重复，swipe → 方向）。
- **回归保障**：现有 6 个三指手势识别测试全绿 + 新增二指/四指测试（TDD 先红后绿）。

## 7. 系统手势策略

- macOS 系统手势映射：二指**左右**滑动 = 「在页面间轻扫」（浏览器前进/后退），**可在系统设置关闭**（触控板 → 更多手势）。
- App 绑定二指左右滑时，**检测系统「页面间轻扫」设置**，若开启则引导用户关闭，关闭后 App 独占识别。
- 二指**上下**滑动（滚动）为刚需，不占用、不做自定义手势目标。
- 其余预设避开系统占用：四指滑动/轻点（系统默认四指左右 = 切换桌面空间，同样需引导关闭或在用户环境已关时可用——**纳入系统手势检测范围**）。

## 8. 安全与边界

- 绑定配置仅改变 App 侧手势→动作映射，**不扩大 Chrome 权限面**：动作均为已实现的标准动作 + 新增的 `chrome.tabs/sessions/clipboard` 类（权限已在扩展 manifest 内，若新增权限需同步 manifest 并评估）。
- Provider 协议新增动作为**向后兼容 case**；旧 `v1` 绑定（`DefaultRules.v1Bindings`）保留为默认，用户覆盖后仍可回退。
- 既有约束延续：测试控制入口默认不可用；E2E 控制 token 隔离；日志不泄漏 token/URL 敏感信息。
- 新增动作若涉及新 Chrome 权限（如 clipboard 写、downloads），需在扩展 manifest `permissions` 声明并纳入安装说明。

## 9. 兼容性

- 协议层：新增枚举 case 向后兼容（旧版 provider 不解读新 case 即忽略）。
- 配置层：旧 `Rule`/`AppConfiguration` 迁移路径保留；新绑定配置为增量键，缺省回退默认绑定。
- 识别层：现有三指手势定义不变，识别行为不变（回归测试保障）。

## 11. 页面加载期间的动作上下文

标签身份与网页内容就绪是两个独立条件。新标签首次导航尚未提交时，Chrome 可能只提供 `pendingUrl`，或暂不提供 URL；这不应阻止已有的标签管理、刷新和历史导航动作。

- `ChromeProvider.context` 在确认活动标签有效后，先登记绑定 `gestureSessionId`、`tabId` 和 deadline 的上下文，再判断页面是否支持链接目标。
- 无有效已提交 URL 时，`pageIdentity` 为空；不使用 `pendingUrl` 伪造已提交页面身份，也不生成 `targetRef`。`requiresTargetRef=false` 返回 `no_target`，`true` 返回 `page_unavailable`，但两者均保留可用于浏览器动作的上下文。
- 切标签、关闭/新建/固定/静音/恢复标签、刷新和前进/后退无需等待页面脚本；仍受原有动作能力、会话、deadline 和当前活动标签身份校验约束。
- 打开/复制链接仍需真实链接目标，打开链接继续校验并消费 guard；复制页面 URL 和滚动仍遵循原实现的页面脚本就绪要求。历史导航仍需有可用历史记录。
- 不修改手势识别、组合仲裁、guard lease、Provider 协议、Chrome 权限或配置模型。此次只修正已有上下文创建入口的条件，不新增候选或 guard 生命周期。

### 回归清单

| 条件 | 期望行为及验证 |
|---|---|
| 只有待导航 URL／URL 完全为空 | 两种 `requiresTargetRef` 请求下，12 类浏览器动作通过真实 Provider 与动作执行器；无页面脚本调用、无伪造链接目标 |
| 页面尚未就绪 | 链接动作拒绝无目标请求；复制页面 URL、页面滚动不可用时明确失败 |
| 请求过期、上下文过期、会话不符、活动标签变化或关闭 | 旧请求无动作副作用；随后独立正常操作成功 |
| 同一标签首次导航提交 | 浏览器动作上下文仍可使用；不把 URL 从空变为有效视为换标签 |
| Provider 分发与持久化 | 副作用前写入 accepted，随后写入同一操作的终态；重复请求不重放；事件不包含待导航敏感参数 |

对应自动化：`extensions/chrome/tests/loadingTabActions.test.ts`。真实触控板步骤见端到端验收清单。
