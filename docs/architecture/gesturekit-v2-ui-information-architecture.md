# GestureKit V2 UI 信息架构契约

> 状态：已确认，作为 Task 10 的前置 UI 设计闸门。
>
> 目的：先固定 App 与 Chrome popup 的信息架构、页面责任、状态文案和交互边界；Task 6–9 后续只接入数据和行为，不得重新扩大 popup 或改变导航结构。

## 1. 范围和执行顺序

本契约不新增产品功能，也不改变实施计划中的 Task 编号。Task 10 分为两个阶段执行：

1. **Task 10A：UI 框架搭建**。在 Task 6–9 前完成 App 窗口、导航、页面骨架、popup 最小布局、状态展示模型和文案映射；使用稳定的占位状态，不接入未完成的 Provider、配置、ledger 或 guard 业务逻辑。
2. **Task 6–9：底层能力开发**。按原计划实现 IndexedDB ledger/outbox、手势会话和规则、Chrome Provider/guard、App 配置主权。
3. **Task 10B：UI 数据接入与验证**。在 Task 9 后将既有页面连接到 `OperationJournal`、`HealthSupervisor`、`SettingsStore`、Provider 会话和配置快照；补齐 UI 自动化测试与真实构建产物验收。
4. **Task 11：端到端验收与 legacy 清理**。仅在 v2 端到端契约通过后，删除旧 popup 配置入口、旧设置反向同步和旧诊断环形数组主存储职责。

Task 10A 不得伪造“已连接”“已同步”“无需权限”等事实；未接入数据时必须使用本契约定义的准备中或不可用状态。

## 2. 信息架构

### 2.1 角色边界

macOS App 是唯一的控制中心，承担用户配置、历史操作、诊断证据、Provider 管理、隐私存储与高级运维。

Chrome popup 是当前页面的上下文提示，不是设置中心、诊断中心或历史记录入口。popup 只显示：

- 当前页面是否支持手势。
- App 和 Chrome Provider 的连接状态。
- 当前手势预设名称。
- 当前页面最近一次操作结果。
- 打开 GestureKit 控制中心和查看相关操作的入口。

popup 不得显示滑块、手势开关、完整设置、推荐设置、历史诊断列表、复制/清空诊断操作或开发者面板。

菜单栏只保留常驻状态、暂停/恢复、打开 GestureKit、一条持续故障摘要和退出。普通成功手势不得导致高频菜单栏状态变化。

### 2.2 App 导航

App 固定侧边栏，顺序如下：

1. **概览**：运行状态、Provider 状态、最近操作、最高优先级待处理问题。
2. **操作记录**：可分页的操作时间线、终态筛选、用户可理解的原因说明和脱敏证据包导出。
3. **手势预设**：当前预设与标准手势映射；V1 不提供任意 DIY 编辑器、三击匹配或动作换绑 UI。
4. **Provider**：认证连接、能力、配置应用状态、离线队列/对账摘要和重新连接入口。
5. **隐私与存储**：双重脱敏、存储使用量、保留策略、不会记录的数据范围和证据导出保留提醒。
6. **高级设置**：系统权限说明、一次性旧配置迁移、Provider 凭据轮换/撤销和开发者自检。

## 3. 页面表现

### 3.1 概览

概览采用四张状态卡片：运行状态、Provider、最近操作、需要处理。需要处理只在存在持续故障、结果未知、监听停止、凭据失效或关键存储不足时显示。多个问题并存时只显示最高优先级问题，其余问题留在对应页面。

### 3.2 操作记录

操作记录使用左侧操作列表和右侧详情的双栏布局。列表按最近活动时间倒序，支持全部、需要关注、结果未知筛选和“加载更多”分页。详情包含：

- 面向用户的手势/动作名称和终态标题。
- “发生了什么”的阶段说明。
- 已脱敏的阶段时间线。
- 导出脱敏证据包按钮。

普通 UI 和证据包均不得展示 URL query/hash、Cookie、页面正文、原始 `targetRef`、协议内部枚举或错误码。导出操作必须提示导出副本不受本地 7 天/50 MB 自动清理控制。

### 3.3 手势预设

手势预设展示当前预设名称、说明和标准映射。Task 9 接入后，App 是唯一写入方，popup 只能读取预设名称。V1 只展示预设，不实现任意新手势、三击、轨迹录制、分享或完整 DIY 编辑器。

### 3.4 Provider

Provider 页面展示用户可理解的连接状态、能力摘要、配置版本是否已应用、离线事件是否已同步和重新连接入口。它不得展示 Provider secret、nonce、session ID、HMAC、原始 IPC 错误或认证错误码。

### 3.5 隐私与存储

隐私与存储页面展示“记录什么/不记录什么”、双重脱敏是否启用、Journal 使用量和保留策略。页面必须说明不会记录 Cookie、网页正文、query/hash 和可逆链接目标。

### 3.6 高级设置

高级设置只放置低频运维能力。权限文案必须基于实际检测结果；在 Task 11 的签名构建验收完成前，只能说明“基础方案预期不需要 Input Monitoring/Accessibility”，不得宣称已证实无需权限。

## 4. 统一状态和文案

所有 UI 使用中文用户文案，禁止泄露协议枚举、错误码和内部字段。每个异常状态必须说明发生了什么以及系统采取的保护措施。

| 场景 | 标题 | 说明/保护措施 |
| --- | --- | --- |
| 首次启动 | 正在准备 GestureKit | 正在检查手势监听和 Chrome 连接；未确认前不显示“运行正常”。 |
| 无 Provider | Chrome 尚未连接 | 手势可识别，但浏览器动作不会执行；提供连接指引。 |
| Provider 断连 | Chrome 连接已中断 | 未确认操作保留诊断信息；恢复后自动对账，不自动重放。 |
| 配置未同步 | 当前预设正在同步 | 同步完成前暂不执行动作，避免使用旧配置。 |
| 页面不支持 | 当前页面暂不支持手势 | 用于浏览器内部页、上下文不可用或能力不匹配。 |
| 页面保护不可用 | 为避免误触，本次操作未执行 | 不显示 `guard_unavailable` 等内部状态。 |
| 结果未知 | 操作结果暂时无法确认 | 已保存完整诊断信息，可在操作记录中查看和导出。 |
| 监听不可用 | 无法开始手势监听 | 只依据实际检测结果解释权限或环境问题。 |
| 存储不足 | 诊断存储空间不足 | 先压缩旧记录；关键证据无法保存时暂停新动作。 |

## 6. UI 框架验收标准

Task 10A 完成时必须满足：

- App 与 popup 已具备本契约的固定导航和页面层级。
- 所有页面都有加载、空、不可用和异常状态的稳定布局。
- App 的页面骨架不依赖 Chrome 专用类型；通过 view model/protocol 接入后续数据。
- popup 不再承担设置、推荐或历史诊断展示。
- 未接入能力必须显示准备中、不可用或连接指引，不能展示伪造状态。
- 窄 popup、App 最小窗口和长文本状态不截断关键含义。

Task 10B 完成时再验证真实数据、分页、证据导出、菜单栏状态、popup 当前页结果和断连/结果未知路径。

## 7. 非目标

- V1 不实现三指三击、任意新组合、手势录制、完整动作换绑、配置分享或多浏览器具体 UI。
- 不在 popup 中恢复任何配置写入、推荐应用或诊断历史能力。
- 不把 Provider 认证秘密、可逆页面信息或原始协议字段暴露给普通 UI。
