# GestureKit v2.5.1

## 概述

补丁版本：应用可打包为正常 macOS 应用启动（不再占用终端），并修复控制中心窗口在 `.accessory` 激活策略下切到其它 App 后不退回、只能一直盖在最前的问题。

## 新增功能

- 无。

## 体验改进

- 新增 `scripts/dev/build-app.sh`：构建并组装 `GestureKit.app`（打包 `OpenMultitouchSupportXCF.framework` 与 rpath、ad-hoc 签名），安装到 `~/Applications`；双击或 `open` 启动，不再需要终端前台运行。
- 控制中心窗口打开时以普通应用窗口呈现（`.regular`），可正常切到其它窗口后面；关闭后回到菜单栏后台（`.accessory`），符合菜单栏软件形态。
- 菜单栏图标改为内嵌常量，打包版不依赖 SPM 资源 bundle，脱离 `.build` 树也能正常加载。
- 版本号从 git tag 派生（`CFBundleShortVersionString` 取最近 tag，`CFBundleVersion` 含提交数），单一来源、不随代码漂移。

## 修复

- 问题：控制中心窗口切到 Chrome 等其它 App 后不退回，只能盖在最前。
- 触发条件：App 固定 `.accessory` 激活策略，加上 `activate(ignoringOtherApps:)`；accessory 应用的窗口层级/激活行为在 macOS 上非标准。
- 修复内容：打开控制中心时切换 `.regular` 并 `makeKeyAndOrderFront`，关闭窗口时切回 `.accessory` 并归还焦点；补充 `applicationShouldHandleReopen`（Dock 图标点击重开窗口）、最小主菜单（避免空菜单占顶栏）与策略切换后的 status item 刷新。

## 兼容性与迁移

- 配置、协议或数据迁移：无。
- 回退方式：回退本 PR 即恢复 v2.5.0 的启动与窗口行为。
- 已知限制：打包版与 `swift run` 启动的开发实例共用单实例锁，同一时刻只能运行一个，并行前需先退出已启动实例（已写入 `docs/operations/本地安装.md` §3）；打包版版本号依赖本机 git tag。

## 验证

- 自动化：`swift test` 230/230 通过；扩展 `npm test` 205/205 通过；打包冒烟（`build-app.sh` 生成 `.app`，启动后 IPC 17653 就绪 + 健康心跳）。
- 手动验证：`open ~/Applications/GestureKit.app` 启动不占终端；打开控制中心切到 Chrome 确认窗口退到后面；关闭窗口确认回到菜单栏（无 Dock 图标）。
