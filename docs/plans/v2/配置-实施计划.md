**Goal:** Add Chrome-extension-side gesture presets, toggles, and a lightweight popup so gesture feel can be adjusted without editing code.

**Architecture:** Gesture execution remains in the Chrome extension. A focused settings module owns defaults, preset application, validation, and `chrome.storage.local` persistence. `nativePortManager` consumes a loaded settings object for thresholds and feature switches, while the popup edits the same storage values.

**Tech Stack:** Chrome MV3, TypeScript, Vitest, existing build script.

## Global Constraints

- Documentation is Chinese-first.
- Do not move the source of truth for this P1 into the Swift app yet.
- Keep P1 small: no arbitrary gesture-action binding, no multi-browser config, no cloud sync.
- Existing Swift protocol and extension behavior from the current working tree must keep passing.

### P1.5：滑动灵敏度同步

**目标：** 让 Chrome 扩展设置控制 Swift 侧轻扫识别灵敏度，并回报 Swift App 是否已应用该设置。

**范围：**
- 在 Swift 侧新增 `GestureRecognitionSettings` 预设：`robust`、`standard`、`sensitive`。
- 新增协议消息 `settings_update` 与 `settings_ack`。
- 让 `GestureRecognizer` 读取可配置的轻扫阈值。
- 通过 native host 与本地 IPC 转发扩展→App 消息。
- popup 增加轻扫灵敏度控件，并显示最近一次同步状态。
- 更新中文优先文档。

**不做：**
- 完整 macOS 设置 UI。
- 任意手势-动作绑定。
- 长诊断历史（保持为后续事项）。

### V2.2：手势配置迁移（App 权威配置）

> 本节取代 P1/P1.5 的「扩展侧为设置来源」模型：配置权威转移到 App `AppConfiguration`，旧 `settings_update` 收口为一次性迁移，不再作为正式写入入口。

**目标：** 让三项已验证 Chrome 手势可独立启用或关闭，并让三档轻扫灵敏度从 App 权威配置稳定驱动启动、运行时和 Chrome Provider 同步。

**架构要点：**
- `AppConfiguration` 保持唯一配置快照；新增配置运行时适配层，在 App 启动和用户修改时以同一份快照构造 `GestureRecognizer`、配置化 `RuleEngine` 与 `RecognitionPlan`。
- 控制中心只调用该适配层（`GestureConfigurationController`），不直接写 `UserDefaults`。
- Chrome 仅接收快照和确认版本，不能写回绑定；配置变更通过既有 `configuration_snapshot` / `configuration_ack` 完成，不改变 Provider Protocol v2 的消息类型。

**约束：**
- 实现必须符合 `docs/product/v2/v2.2-配置契约.md`。
- 只开放三指点按链接、三指左滑、三指右滑和三档灵敏度；不展示未端到端验证的边缘点按或双击关闭标签。
- 关闭链接打开绑定必须移除 `link_click` guard；普通网页点击不得受影响。
- 项目文档与用户文案中文优先；协议字段、动作 ID 和代码标识保持原文。

**任务分解：**

- **Task 1：配置化动作解析与兼容迁移**
  - 文件：`Sources/GestureKitCore/Rules/RuleEngine.swift`、`Sources/GestureKitCore/Rules/RuleModels.swift`、`Sources/GestureKitCore/Settings/AppConfiguration.swift`、`apps/macos/GestureKitApp/Sources/GestureKitApp/ConfigurationMigration.swift` 及对应测试。
  - 接口：新增 `RuleEngine.init(configuration: AppConfiguration)`；新增 `ComposedGesture.gestureDefinitionID: String`；`RuleEngine.resolve` 仅从启用的 `BindingRule` 匹配，无匹配返回 `nil`；`AppConfiguration` 增加仅表达 V2.2 UI 可配置项的稳定访问器。
  - 关键步骤：为已启用/已关闭链接绑定、左右滑绑定与 `targetKind` 不匹配写失败测试；旧 schema 配置迁移补齐默认三项启用与标准灵敏度并递增配置版本；拒绝未知未来 schema，不静默回退默认配置。

- **Task 2：App 运行时配置事务**
  - 文件：新建 `apps/macos/GestureKitApp/Sources/GestureKitApp/GestureConfigurationController.swift`；修改 `Runtime.swift`、`RuntimeControl.swift`、`AppDelegate.swift` 及测试。
  - 接口：`loadOrCreate()`、`updateBinding(id:enabled:)`、`updateSensitivity(_:)`、`restoreDefaults()`、只读 `snapshot()`；每次写入生成更高 `configurationVersion`。
  - 关键步骤：`GestureKitRuntime.apply(configuration:)` 顺序为先校验并构造新运行时对象 → 保存 → 原子替换运行时状态 → 发 Provider 快照；Provider 未确认不回滚已保存且已应用的 App 配置；删除正式路径对 `loadRules()` 的依赖。

- **Task 3：控制中心手势与操作页面**
  - 文件：修改 `ControlCenterPresentation.swift`、`ControlCenterDataSource.swift`、`ControlCenterPages.swift`、`ControlCenterView.swift` 及测试。
  - 接口：`PresetPageState` 替换为 `GestureConfigurationPageState`；控制中心导航文案从「手势预设」改为「手势与操作」。
  - 关键步骤：只呈现三项契约内手势，不呈现边缘点按或双击关闭标签；恢复默认只重置开关和灵敏度；UI 写入全部通过 `RuntimeControlling` 到 Task 2 控制器，不泄露规则 ID、动作枚举或 Provider 错误码。

- **Task 4：Chrome 配置确认与 V1 设置迁移边界**
  - 文件：修改 `extensions/chrome/src/background/settingsSync.ts`、`extensions/chrome/src/settings/gestureSettings.ts`、`extensions/chrome/src/background/index.ts` 及对应测试。
  - 接口：Provider 对 `configuration_snapshot` 只缓存 `storeEpoch/schemaVersion/configurationVersion` 与只读配置 JSON，并按收到的版本回传 `configuration_ack`。
  - 关键步骤：旧 `settings_update` 仅在 App 迁移标记不存在时允许一次性导入，之后返回 `legacy_settings_write_rejected` 并保持现有配置版本；删除扩展侧把轻扫设置当作 App 正式运行时来源的行为。

- **Task 5：端到端回归、文档和发布准备**
  - 文件：修改 `docs/architecture/配置派生交互护盾-设计.md`、`docs/operations/端到端检查清单.md`、`docs/operations/本地安装.md`、`docs/product/v2/v2.2-配置契约.md`、`README.md`。
