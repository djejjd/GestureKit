# V2.5 手势绑定与手势系统开放 — 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans` 按任务逐项实现。Steps 使用 `- [ ]` 勾选跟踪。

**版本语义：** V2.5 为**功能版本**：开放手势→动作绑定（用户可配映射）+ 开放预设手势集（识别器支持 2/3/4 指）。在 v2.4.2 文档整改后的代码库上实现。新增 Provider 标准动作（向后兼容 case），不破坏现有三指手势识别。

**目标：** 用户在控制中心可配置"手势 → 动作"映射并立即生效；识别器支持预设多指手势（二指左右滑动、四指轻点/滑动等）；现有 6 个三指手势识别不退化。

**设计依据：** `docs/architecture/v2.5-手势绑定与手势系统-设计.md`（grilling 共识 + 现状核验）。

## 范围

**包含：**
- 绑定开放：手势→动作映射可配置（现有 7 个标准动作 + 新增 Tab 管理类 + 链接页面类），上下文约束系统预设
- 手势开放：预设手势集（二指左右滑动、四指轻点/滑动），识别器增量参数化
- 系统手势检测/引导（二指左右滑 → 提示关闭系统「页面间轻扫」）
- 控制中心绑定配置 UI

**非目标：**
- DIY 手势编辑器（任意手指数/原语/方向/区域组合）
- 上下文约束（链接上 vs 空白处）开放给用户
- 进阶动作（翻译/深色模式/分屏/TTS/下载）——延后单独排

## 全局约束（沿用既有）

- 范围与验收依据：`docs/product/v2/v2.4-可靠性契约.md`；Provider 协议新增为向后兼容 case。
- 每项实现遵循 TDD：先运行失败测试 → 最小实现 → 任务级与相关全量测试。
- 项目文档中文优先；代码、命令、协议字段和路径保持原文。
- 新增 Chrome 权限（clipboard/downloads 等）需同步扩展 manifest 与安装说明。

## 任务

### Task 1：绑定配置模型与持久化

- [ ] **Step 1**：新增用户绑定配置模型（基于 `BindingRule`，默认 `DefaultRules.v1Bindings` + 用户覆盖；支持启用/禁用单条）。
- [ ] **Step 2**：`SettingsStore` 持久化用户绑定（增量键，缺省回退默认）；TDD 覆盖保存/加载/回退。
- [ ] **Step 3**：`RuleEngine` 接入用户绑定（默认 + 覆盖合并，优先级保留）；TDD 覆盖覆盖生效与回退。
- [ ] **Step 4**：提交。

### Task 2：新增标准动作（Tab 管理 + 链接页面）

- [ ] **Step 1**：Core `StandardActionID` 扩展新增动作：Tab 管理类（open_new_tab / pin_tab / toggle_mute / close_other_tabs / restore_tab）+ 链接页面类（copy_link / copy_page_url / scroll_to_top_bottom）。
- [ ] **Step 2**：Provider 协议 v2 新增动作定义（类型↔payload 映射，向后兼容）；schema + TS 类型同步。
- [ ] **Step 3**：Chrome 扩展侧执行实现（`chrome.tabs/sessions/clipboard` 等）；manifest 权限同步（如需）。
- [ ] **Step 4**：TDD：协议解码测试 + 扩展侧单测（vitest）+ 真实 Chrome 冒烟（新动作触发）。
- [ ] **Step 5**：提交。

### Task 3：识别器增量参数化 + 预设手势集

- [ ] **Step 1**：`GestureRecognizer.observe`：`fingerCount == 3` 写死 → 按活跃手势定义集匹配 fingerCount；保留 session 状态机语义（升高→reject、降低→classify、抬指→classify）。
- [ ] **Step 2**：`classify` 按命中定义的 primitive/direction/region 输出对应 `ComposedGesture`。
- [ ] **Step 3**：新增预设 `GestureDefinition`：二指左右滑动、四指轻点、四指左右滑动（避开系统占用的取舍见设计 §7）。
- [ ] **Step 4**：`ComposedGesture`/`GestureType` 新增对应 case（向后兼容）。
- [ ] **Step 5**：TDD：现有 6 个三指手势识别测试**全绿保底** + 新增二指/四指识别测试（先红后绿）。
- [ ] **Step 6**：提交。

### Task 4：控制中心绑定 UI + 系统手势引导

- [ ] **Step 1**：控制中心绑定配置页（手势列表 → 动作下拉选择；默认/用户覆盖态显示；启用开关）。
- [ ] **Step 2**：立即生效（改配置 → RuleEngine 热更新）。
- [ ] **Step 3**：系统手势检测：读取 macOS「在页面间轻扫」设置（`defaults read` 触控板设置）；绑定二指左右滑时若开启则提示引导关闭。
- [ ] **Step 4**：TDD/UI 测试（SwiftUI + 数据源单测）。
- [ ] **Step 5**：提交。

### Task 5：全量验证与真实 Chrome 门

- [ ] **Step 1**：`swift test`、`npm test`、`npm run build`、node e2e 单测、dry-run 全绿。
- [ ] **Step 2**：本机真实 Chrome：绑定重绑生效验证 + 新动作（Tab 管理/链接页面）触发验证 + 二指左右滑（关闭系统「页面间轻扫」后）不冲突。
- [ ] **Step 3**：CI（PR 触发）质量门绿。

## 验收标准

- 用户可在控制中心重绑「手势 → 动作」，保存后立即生效；默认绑定可回退。
- 现有 6 个三指手势识别不变（识别测试全绿）；新增二指左右滑动、四指轻点/滑动可用。
- 二指左右滑（系统「页面间轻扫」关闭后）触发绑定动作，不与系统滚动冲突；App 有检测与引导。
- 新增动作（Tab 管理类/链接页面类）在真实 Chrome 生效，协议向后兼容。
- 通用 CI（swift/extension/scripts）全绿。
- 无 token/凭据泄漏；无残留进程或临时目录。
