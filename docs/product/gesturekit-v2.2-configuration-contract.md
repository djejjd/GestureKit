# GestureKit V2.2 手势配置契约

> 状态：待用户审阅。
>
> 目标：将当前已端到端验证的 Chrome 手势能力从固定行为收敛为可理解、可开关、可持久化且真实作用于运行时的用户配置；为后续新增手势和浏览器动作保留统一配置边界。

## 1. 契约目的

本契约定义 V2.2 的产品范围、配置语义、架构边界和验收条件。实现、测试与审核必须遵循本契约；任何扩大可配置手势或浏览器动作范围的变更，必须先更新本文件并获得确认。

V2.2 不以“预设模式”组织用户配置。用户应能直接理解每项手势会执行什么浏览器操作，并独立启用或关闭它。

## 2. 用户可见范围

### 2.1 手势与动作关联

macOS App 的“手势预设”页面改为“手势与操作”。页面仅展示下列已端到端验证的项目：

| 手势 | 浏览器操作 | 默认状态 |
| --- | --- | --- |
| 三指点按链接 | 在当前标签右侧打开链接并切换到新标签 | 启用 |
| 三指左滑 | 切换到下一个标签页 | 启用 |
| 三指右滑 | 切换到上一个标签页 | 启用 |

每项均提供独立开关。关闭后，App 不得为该手势派发对应浏览器动作；其他已启用手势继续正常工作。页面显示中文手势名称、动作名称、开关状态及不可用原因，普通 UI 不得显示协议动作 ID 或规则内部字段。

V1 模型中已有但当前输入识别层尚未端到端产出的左右边缘点按、三指双击关闭标签，不得在 V2.2 显示为可配置或可用项目。它们在后续完成输入识别、运行时决策与端到端验收后，以同一列表项形态接入。

### 2.2 轻扫灵敏度

页面提供独立的三档轻扫灵敏度：

| 档位 | 最小滑动距离 | 水平比例 | 时长范围 |
| --- | ---: | ---: | --- |
| 稳健 | `0.11` | `1.8` | `60-350ms` |
| 标准 | `0.09` | `1.5` | `60-420ms` |
| 灵敏 | `0.075` | `1.25` | `50-480ms` |

灵敏度只影响左右轻扫的识别阈值，不改变点按行为、浏览器动作含义或链接交互保护。默认值保持 V2.1 的“标准”。

### 2.3 配置状态与恢复

每次用户修改均须明确显示以下状态之一：

- `已保存`：配置已原子写入 App 权威存储。
- `运行中已应用`：当前 App 的识别与动作决策已使用新配置。
- `Chrome 已确认`：活动 Chrome Provider 已确认对应配置版本。
- `未能应用`：显示用户可理解原因与可执行的恢复路径，不得显示为已生效。

页面提供“恢复默认配置”。恢复操作仅还原本契约列出的三项开关和轻扫灵敏度，不删除操作记录、诊断日志、Provider 连接信息或证据包。

操作记录详情必须关联当时的配置版本与配置摘要，以便判断一次动作是否受开关或灵敏度调整影响；不得记录原始页面目标或其他敏感数据。

## 3. 配置与运行时边界

`AppConfiguration` 是手势定义、启用状态、动作绑定和 `recognition` 阈值的唯一权威来源。V2.2 必须消除以下双轨行为：

- App 启动后使用默认灵敏度，而没有加载已保存的 `AppConfiguration.recognition`。
- 运行时动作决策继续从旧 `Rule` 存储读取，而用户界面修改的是 `BindingRule`。
- Chrome extension 的旧 `settings_update` 迁移链路被视为正式配置写入入口。

配置变更必须作为单一事务处理：校验配置、写入新版本、编译运行时识别与绑定计划、替换运行时状态、同步活动 Provider，并记录最终应用状态。任何一步失败不得让 UI 声称新配置已生效。

Chrome Provider 只能缓存 App 下发的配置快照和确认其版本，不得保存或推断用户手势-动作关系。Provider 不可用时，App 仍可保存配置，但必须明确 Chrome 尚未确认；恢复连接后按最新配置版本同步。

链接交互保护仍由启用的 `BindingRule` 派生：只有“三指点按链接”处于启用状态时才 arm `link_click` guard。关闭该项后，普通网页链接点击不得被暂存、阻止或延后。

## 4. 非目标

V2.2 不交付：

- 二指、四指、自由录制、任意轨迹或任意新组合手势。
- 未验证的边缘点按、双击关闭标签的配置入口。
- 任意浏览器动作组合、宏、AppleScript、shell command 或其他 App 自动化。
- Safari、Firefox 或其他浏览器 Provider。
- “专注模式”“导航模式”等人为预设模式。
- 云同步、配置分享或多人配置管理。

## 5. 迁移与兼容

- 未修改配置的既有用户升级后，默认行为必须保持 V2.1：三项已验证手势均启用，灵敏度为“标准”。
- V1 extension 侧轻扫设置仅用于一次性导入到 `AppConfiguration`；导入完成后，extension 不能反向覆盖 App 配置。
- `AppConfiguration` schema 的升级必须可识别旧快照；缺失 V2.2 新字段时按上述默认值补齐。未来 schema 不兼容时应拒绝加载并提供恢复默认配置的明确路径，不能静默丢弃用户配置。

## 6. 验收标准

### 6.1 功能

- 三项已开放手势均可独立启用和关闭；关闭后不派发对应动作，重新启用后恢复执行。
- 三档灵敏度真实传给运行中的 `GestureRecognizer`，并使左右轻扫的边界识别结果符合对应阈值。
- 配置重启 App 后保持；启动后的识别器和动作决策直接使用已保存配置。
- 默认升级路径保持 V2.1 用户行为。
- 恢复默认配置仅恢复本契约范围内的开关与灵敏度。

### 6.2 同步与失败

- Provider 已连接时，App 仅在收到对应配置版本确认后显示“Chrome 已确认”。
- Provider 未连接或同步失败时，配置仍可保存并在 App 运行时生效，但 UI 明确显示未确认原因。
- Provider 重连后只同步最新配置版本，旧版本确认不得覆盖较新状态。
- 关闭链接打开关联后，正常单指链接点击立即按网页默认行为处理，且不会出现 `link_click` guard。

### 6.3 回归与诊断

- V2.1 已验证的三指打开链接保护链路保持有效：启用时只打开新标签，原标签不导航。
- 操作记录显示的配置版本与派发动作时实际使用的版本一致。
- 普通 UI、日志和 Chrome 存储不泄露原始手势配置以外的敏感网页数据、会话凭据或内部协议字段。

## 7. 变更控制

以下变更必须先更新本契约并重新确认：

- 新增可配置手势、浏览器动作或 Provider。
- 改变 `AppConfiguration` 的唯一权威来源。
- 允许 Chrome extension 写入或覆盖用户手势绑定。
- 改变链接交互保护的 fail-open 或恢复语义。
- 引入自由规则编辑、宏、云同步或预设模式。
