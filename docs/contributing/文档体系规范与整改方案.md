# 文档体系规范与整改方案

> 本文档双职：既是**文档治理规范**（长期约束），也是**本次整改的执行方案**（一次性迁移任务）。整改完成后移除"执行方案"部分，只保留规范。

## 一、问题与目标

现状问题：`docs/` 下 45+ 文件全部英文名、`plans/` 17 个文件命名维度混乱（P 编号/版本号/主题混用）、无生命周期状态、补丁即新开文件（如 v2.4.1 之于 v2.4）、无目录索引。

目标：**中文文件名、有序可排序、可回溯、分类合理、同一主题不因迭代新增文件**。

## 三、命名规范

通用格式：`<前缀>-<中文主题>.md`。主题用中文，用 `-` 连接，不含空格；前缀保证排序。

- **adr/**：`0001-` 递增编号开头。
- **plans/**：分 `v1/`（历史）与 `v2/`（当前）子目录；v2 内不含版本号前缀（版本迭代更新同一文件），形如 `链接可靠性-实施计划.md`；v1 历史带版本前缀 `v1-产品实现计划.md`。
- **product/**：分 `v1/`、`v2/` 子目录，版本前缀 `v2.4-可靠性契约.md`——契约按版本各一份，旧版本只更新不新增。
- **releases/**：`<版本>-变更记录.md`（版本即排序键）。
- **quality/**：日期前缀 `YYYY-MM-DD-<主题>.md`。
- **reserved 英文名**：`README.md`、`CLAUDE.md`、`CLAUDE.zh.md`、`AGENTS.md`、`CONTRIBUTING.md`、`.gitignore` 为工具/惯例约定名，不改。

## 四、文件头元信息（每篇必填状态块）

每个文档开头统一元信息块，驱动"可回溯"：

```markdown
---
状态: in-progress            # draft | in-progress | completed | superseded
创建: v2.4                  # 版本或日期
最后更新: 2026-08-07
关联:                        # 相关文档路径
  - ../architecture/v2-UI信息架构.md
---
```

- **plans/** 必填 `状态`；v2 内 `completed`/`superseded` 就地标记，历史版本文档归 `plans/v1/`；`superseded` 必须给出 `关联` 指向新文件。
- **product/releases/** 必填 `创建` 版本。

## 五、修订记录与防膨胀规则（根治"每次改点新增文件"）

1. **同一主题的迭代更新原文件**：在文件内追加"修订记录"小节（日期 + 变更 + 动机），更新元信息 `最后更新`，**不新开文件**。例：v2.4.1 补丁 → 并入 `链接可靠性-实施计划.md` 的修订记录，不建 `链接可靠性补丁.md`。
2. **补丁判据**：是同一主题的收敛/补丁（不新增功能面）→ 并入原文件；有独立发布与验收生命周期 → 才允许新文件，且元信息必须 `superseded` 旧文件并 `关联` 指向。
3. **新增文件检查清单**（全否才允许新建）：能否更新现有文件？能否归入既有版本/主题域？是否属于既有分类？
4. **允许新建的场景**：新主题域计划、新版本发布（releases/）、新 ADR、新事故复盘（quality/）、新调研/实验（research/）。
5. **plans/v2/ 一主题域至多一个计划文件**：新旧靠状态字段区分，`completed`/`superseded` 就地标记，历史版本文档归 `plans/v1/`。

## 七、执行步骤（分阶段）

**阶段 1（必做，低风险）：改名 + 索引**
1. 按映射表 `git mv` 全部改名（保留历史），`.gitignore`/`RELEASE_TEMPLATE` 之外。
2. 新增 `docs/README.md`、`docs/plans/README.md`。
3. 更新外部引用（见第八节清单）+ docs 内部互链（grep 全部 docs 路径逐一改）。
4. 验证：`git grep` 旧英文文件名残留应为 0；`npm test`/`swift test` 不受影响（无代码引用 docs）。

**阶段 2（plans 收敛）：合并 + 归档**
1. v2.4.1 内容并入 `链接可靠性-实施计划.md`（修订记录），删除 v2.4.1 文件。
2. p3+v2.3 合并入 `安装连通性-实施计划.md`；p1+p15+v2.2 合并入 `配置-实施计划.md`；p2+p21-25+p4 合并入 `诊断与推荐-实施计划.md`。合并以"章节+修订记录"方式，不重写主体内容。
3. v1 五个文件移入 `plans/archive/`，元信息加 `状态: completed`。

**阶段 3（可选）：主题重叠深化**
对合并后的文件逐个评审内容重叠度，进一步精简；不做可不做，避免返工。

## 九、验收标准

- 所有英文文件名（保留名除外）迁移为中文名，`git mv` 保留历史；`git grep` 无旧名残留。
- 文档有序：adr 编号 / releases 版本 / quality 日期均自然排序；plans/ 仅进行中文件，archive/ 独立。
- 可回溯：每篇文件头有元信息；迭代通过"修订记录"而非新文件。
- `docs/README.md` 索引齐全，dead link 为 0（用脚本或手工核对）。
- 外部引用全部更新，无指向旧路径的断链。
